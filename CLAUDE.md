# Notes for working on Routes

Routes is a World of Warcraft addon (Lua 5.1, no JIT) that draws gathering
routes. `Routes.lua` is the addon and its options UI, `TSP.lua` contains the
two algorithms: route clustering (`TSP:ClusterRoute`) and route optimization
(`TSP:SolveTSP`).

## Tests

`TSP.lua` can be tested outside the game, `Routes.lua` cannot (it needs Ace3
and the game UI). Run from the addon root with a plain Lua 5.1 interpreter:

    lua5.1 tests/cluster_test.lua          # clustering, ~1s
    lua5.1 tests/tsp_test.lua              # route optimizer, ~40s
    lua5.1 tests/tsp_test.lua --check      # with assertions inside the solver
    lua5.1 tests/tsp_test.lua --perf       # adds the large cases, ~10 min

Both runners take a Lua pattern to select cases, `--file PATH` to test another
copy of `TSP.lua`, and document their other options in their header.

- Run both suites after any change to `TSP.lua`, and `--check` after changing
  the moves, the kicks or the taboo handling of the solver.
- Changes to `Routes.lua` can only be syntax checked (`loadstring` after
  stripping the UTF-8 BOM). Say so, and ask for an in-game test.
- `tests/wow_shims.lua` stubs the WoW API. Its global `random` is a
  deterministic generator (`shims.SeedRandom`), which is what makes the
  optimizer tests reproducible.
- `tests/data` is generated by `cluster_gen.lua` and `tsp_gen.lua`, which is
  deterministic. Do not regenerate it casually: the baselines in it come from
  `cluster_reference.lua` and `tsp_reference.lua`, frozen copies of the
  original implementations, and regenerating all optimizer baselines takes
  several minutes. Pass a pattern to regenerate only some cases.
- `tests/tsp_extract.lua` turns a route from a saved variables file into test
  cases. `real_herbs_475*` is such a route, its optimum is very likely
  62814.11 yards (many runs end exactly there, none below).

## Clustering (`TSP:ClusterRoute`)

- Its result must stay identical to `tests/cluster_reference.lua`, including
  the order of the clusters and how ties are broken (smallest distance, then
  route order). The tests compare against it exactly. Only the returned route
  length may differ in the last digits.
- This is why distances are compared as `(dx^2 + dy^2)^0.5` and not squared:
  squaring changes which distances are equal.
- Candidate pairs come from a grid with cells of the cluster diameter and are
  kept in a heap. Entries are not removed from the heap, they carry a stamp
  and are skipped if a cluster changed after it.

## Route optimizer (`TSP:SolveTSP`)

- Local search (2-opt and Or-opt over neighbour lists) from a greedy route or
  the given route, whichever is cheaper, followed by kicks: swap 2 adjacent
  segments, improve again, undo if the route is not cheaper.
- Every change to the route goes through `reverse()`, which is what makes
  the undo journal work. Keep it that way.
- `cost` is kept up to date incrementally and includes the taboo penalties,
  the length that is returned is recalculated without them.
- A leg that crosses the outline of a taboo region costs twice its length
  plus the zone width. The crossing test must always be asked with the 2
  nodes in the same order, its answers are cached and the cache is emptied
  when it is full.
- The result is never worse than the route that was passed in, and running it
  again continues from that route.
- There is no NxN matrix and no limit on the number of nodes anymore.
  Distances are calculated when needed.

Tuning, measured on the test routes including the real one:

- 10 neighbours of which 2 per quadrant: without the quadrant neighbours,
  routes with dense groups of nodes were up to 5% longer.
- Kicks swapping segments of up to 100 nodes beat 30, 60 and 150, also for
  the same run time.
- Most of the gain comes from the first 5 to 10 kicks per node. The foreground
  optimization does 10 per node, the background one gives up after 30 per
  node without an improvement (`GetTSPParameters` in `Routes.lua`).
- Tried and dropped, no better for the same run time: moving segments of any
  length (1.7 times slower per kick), 12 to 16 neighbours, and an "extra
  optimization" option for 5 times the kicks.

## Background tasks

- Clustering and optimizing can run as coroutines that are resumed once per
  frame. `yield()` gives control back after `YIELD_BUDGET` milliseconds of
  work, the solver uses its own `tick()` for that which also reports progress.
- Read all input before the first yield: the route table can change while a
  background task runs (nodes are inserted and deleted automatically).

## Things to know

- `TSP.lua`, `Routes.lua` and the locale files start with a UTF-8 BOM, which
  WoW accepts and plain Lua does not.
- Only `Locales/Locale-enUS.lua` contains strings, the other locales are
  filled in by the packager. Changing an enUS key orphans its translations.
- In shell heredocs, backslash escapes in Lua or Python source can get
  mangled. Write such scripts to a file instead.
- `tests` and this file are not part of the packaged addon (`.pkgmeta`).

## Open items

- The Stop button, the removed node limit and the guards against clustering
  and optimizing the same route at once were not all verified in game.
- The result of a background optimization replaces the route without
  checking that it is still the same route: a node that was inserted
  automatically in the meantime is lost. Background clustering checks this
  (`callbackClusterFinished`), background optimizing does not.
- After an error in a background optimization the Stop button stays enabled
  until the options panel is refreshed.
- The progress text of a background optimization shows the cost including
  taboo penalties as "yards".
- The order dependence of the taboo crossing test is fixed but has no test
  that fails without the fix.
- Clustering could use the centre of the smallest enclosing circle instead of
  the centroid as the cluster point. That gave 8 to 15% fewer clusters in a
  trial, but changes what users get and was not done.
